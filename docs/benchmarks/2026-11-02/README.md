# Исправление скорости передачи, 2 ноября 2026

На Mac M4 Pro / 48 ГиБ / macOS 26.6.2 регрессия передачи устранена в повторных
AOT-замерах. Условия совпадают с [первым сравнением](../2026-10-31/README.md):
Java 17.0.17, Dart 3.13.7, отдельные процессы, localhost, реальные gRPC-ядра,
запись файлов и проверка SHA-256, три прогрева и семь измерений.

| Нагрузка | Java, медиана | Исправленный Dart AOT, медиана | Java / Dart, МиБ/с |
|---|---:|---:|---:|
| 1 × 100 МиБ | 0,4173 с | 0,2947 с | 239,66 / 339,33 |
| 20 × 1 МиБ | 0,0865 с | 0,0564 с | 231,32 / 354,63 |

Все 420 полученных файлов, включая прогревочные, независимо сверены Python по
размеру и SHA-256. [Сырые результаты](transfer-macos-arm64.json).
При первой передаче в этой серии 100 МиБ заняли 0,338 с у Dart и 0,591 с у Java.
Сервер теперь проверяет нативный SHA-256 перед открытием порта: загрузка библиотеки
относится к подготовке сервера, которая в обоих приложениях происходит до начала
этого таймера. В UI подготовка запускается после первого кадра; данные файла заранее
не читаются и не хешируются.
Холодный старт, физическая сеть и влияние VPN этим тестом не измеряются.

## Причина и исправление

До изменений [короткое повторение](diagnostic-before.json) подтвердило 6,697 с у
Dart против 0,464 с у Java на 100 МиБ. Самостоятельные AOT-пробы показали около
0,42 с на SHA-256, 0,01 с на protobuf encode/decode и 0,04 с на запись 100 МиБ.
CPU-профиль JIT использовался только для локализации, не для численного сравнения AOT.

Основной провал — обратная связь управления потоком http2 2.3.1. Получатель
отправлял WINDOW_UPDATE на каждый фрагмент, а отправитель расходовал даже крошечный
кредит немедленно. Размер сообщения с 64-КиБ содержимым превышал 65535-байтное окно,
и передача дробилась всё сильнее. На одном диагностическом прогоне после увеличения
окна потока было 46 294 DATA-фрейма по 71 байту, помимо других мелких фрагментов.

Теперь окно потока составляет 1 МиБ, а подтверждения объединяются до 16 КиБ на
поток/соединение. Остаток отправляется максимум через 1 мс или перед другими
исходящими кадрами. Порядок управляющих кадров, полный объём кредитов, обратное
давление сокета, ограничение входящего gRPC-сообщения и отмена сохранены.
Тест с 1000 маленькими подтверждениями воспроизвёл проблему до исправления.
Синхронные исходящие HTTP/2 фреймы также собираются в socket-записи до 64 КиБ
с выдачей остатка в следующей микрозадаче. Запись на диск и хеширование получателя
группируются в ограниченные порции до 1 МиБ плюс один сетевой блок; сетевой блок
остаётся не больше 64 КиБ. Полный файл в память не загружается.

После этого ограничением стало хеширование. SHA-256 перенесён на потоковый
[webcrypto/BoringSSL](https://pub.dev/packages/webcrypto), с одним блоком в обработке
и массовым копированием типизированных байтов. Адаптер публичного List/Iterable API
устраняет побайтовый обход skip/take перед передачей в нативную библиотеку.
Проверка не отключалась и алгоритм не менялся. Память под целый файл не выделяется.

## Проверки и воспроизведение

- Локальный `flutter analyze` — без замечаний; 51 тест прошёл, LAN-тест пропущен.
- Стенд совместимости предварительно собирает Java и Dart AOT с native assets,
  чтобы компиляция на чистом CI не расходовала сетевой таймаут.
- Передача Java ↔ Dart прошла в обе стороны: один файл, пакет, пустой файл,
  одинаковые имена и Unicode.
- На изолированном Android 17 ARM64 эмуляторе с 16-КиБ страницами памяти прошла
  реальная передача через UI, сверка полученного файла, PNG в буфере и список файлов.
- Добавлены тесты объединения кредитов, таймера, отмены/обратного давления,
  ошибок и переполнения, а также SHA-256 против независимого Dart-эталона.
- В CI добавлены AOT-замеры на четырёх desktop runner. Порог регрессии — Dart/Java
  не выше 1,20 по медиане обоих сценариев; запас учитывает шум общих runner.
  Результаты сохраняются даже при превышении порога.

С нативными зависимостями нужен CLI-бандл: `dart compile exe` не включает их.

```sh
./gradlew :core:prepareTransferBenchmark
cd flutter_app
dart build cli --target=tool/benchmark.dart --output=build/transfer-benchmark
cd ..
python3 scripts/benchmark_transfer.py \
  --java /path/to/jdk17/bin/java \
  --classpath core/build/benchmark-classpath.txt \
  --dart-aot flutter_app/build/transfer-benchmark/bundle/bin/benchmark \
  --output /tmp/transfer-results.json --max-dart-ratio 1.2
```

На Windows executable имеет расширение `.exe`; для сборки BoringSSL нужен NASM.
Сборке нужен CMake. На локальном Mac без полного Xcode использовалась временная
обёртка CMake, добавляющая при конфигурации
`-DCMAKE_OSX_SYSROOT_INT=/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk`
и `-DSDK_VERSION=26.5`. Она не меняла SDK, сторонние пакеты или настройки системы.
