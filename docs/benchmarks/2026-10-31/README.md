# Java и Dart: замеры TransportationFiles, 31 октября 2026

На этом Mac Flutter/Dart открывает окно в 3,38 раза быстрее JavaFX. Однако текущее
Dart-ядро передачи медленнее Java-ядра: примерно в 19,9 раза на одном файле 100 МиБ
и в 7,22 раза на пакете из 20 файлов по 1 МиБ. Перенос пока ускорил запуск,
но не передачу файлов. Это сравнение двух реализаций приложения, а не языков вообще.

## Условия

- Apple M4 Pro, 48 ГиБ RAM, macOS 26.6.2 ARM64.
- Java: Microsoft OpenJDK 17.0.17 ARM64; эта же версия входит в packaged Java app.
- Dart 3.13.7, Flutter 3.47.9. UI — готовая release-сборка; стенд передачи — `dart compile exe` (AOT).
- Исходный код приложения: `cc7216a`; локальный Flutter app из CI для `dcf64eb`
  (следующий `cc7216a` меняет только диагностику Python-скриптов запуска).
- Замеры выполнялись последовательно, без параллельной сборки или второго бенчмарка.
  Настройки VPN, firewall и сети не менялись. Кеши ОС не очищались.

## Запуск готового приложения

11 новых процессов каждой версии с чередованием порядка Java/Dart. Первое наблюдение
отделено от медианы остальных десяти. Таймер начинается до запуска процесса и
заканчивается при появлении маркера первого кадра, опрос каждые 10 мс.

| Метрика | JavaFX | Flutter/Dart AOT |
|---|---:|---:|
| Медиана 10 повторных запусков | 0,6765 с | 0,200 с |
| Минимум–максимум | 0,671–0,702 с | 0,189–0,209 с |
| Первое наблюдение в серии | 0,916 с | 0,260 с |

Это приблизительная готовность первого кадра: Java использует два импульса
AnimationTimer, Flutter — addPostFrameCallback. Java запускает сервер перед окном,
Flutter инициализирует модель асинхронно; стенд дополнительно дожидается готовности
сервера Flutter, но это ожидание не входит в показатель первого кадра.
Первое наблюдение **не является замером холодного старта** после перезагрузки.

Сырые данные: [startup-macos-arm64.json](startup-macos-arm64.json).

## Передача файлов

Отдельные процессы отправителя и получателя: Java → Java и Dart AOT → Dart AOT,
адрес `127.0.0.1`, динамические порты. Использованы реальные TransferClient/TransferNode
и TransferSender/TransferNode приложения: gRPC, проверка размеров и SHA-256,
временные файлы и финальное сохранение. UI и поиск устройств в этот тест не входят.

Для каждой пары и нагрузки — новые процессы, одно соединение, три прогревочных
передачи и семь учитываемых. Таймер охватывает вызов send до подтверждения получателя,
включая автоматическое согласование, чтение, хеширование и запись; запуск VM исключён.
В первом сценарии первой измерялась Java, во втором — Dart.

| Нагрузка | Java, медиана | Dart AOT, медиана | Java / Dart, МиБ/с |
|---|---:|---:|---:|
| 1 × 100 МиБ | 0,5948 с | 11,8255 с | 168,13 / 8,46 |
| 20 × 1 МиБ | 0,1222 с | 0,8821 с | 163,70 / 22,67 |

Диапазоны: 100 МиБ — Java 0,591–0,599 с, Dart 11,026–14,613 с;
20 × 1 МиБ — Java 0,117–0,127 с, Dart 0,852–0,928 с.

Данные созданы заранее детерминированным генератором, без разреженных файлов;
протокол не использует сжатие. После измерений Python независимо сверил размер,
SHA-256 и количество **всех 420 полученных файлов**, включая прогревочные.
Эта дополнительная проверка и генерация данных не входят в таймер.

Это скорость текущего кода через loopback и локальное хранилище с кешами ОС,
не скорость Wi-Fi или пары Windows ↔ Mac. Реализации библиотек и записи различаются:
например, Dart явно вызывает flush перед закрытием файла, Java закрывает OutputStream.
Гарантии записи не выравнивались искусственно. Причина отставания Dart не профилировалась;
приписывать весь разрыв самому языку или конкретно SHA-256 пока нельзя.

Сырые данные: [transfer-macos-arm64.json](transfer-macos-arm64.json).

## Повторение

Из корня репозитория, Python 3.9+, JDK 17 и Dart из указанной версии Flutter:

```sh
./gradlew :core:prepareTransferBenchmark
cd flutter_app
dart compile exe tool/benchmark.dart -o /tmp/transportfiles-benchmark-dart
cd ..
python3 scripts/benchmark_transfer.py \
  --java /path/to/jdk17/bin/java \
  --classpath core/build/benchmark-classpath.txt \
  --dart-aot /tmp/transportfiles-benchmark-dart \
  --output /tmp/transfer-results.json
python3 scripts/benchmark_startup.py \
  --java-app /path/to/packaged-java-executable \
  --dart-app /path/to/packaged-flutter-release-executable \
  --output /tmp/startup-results.json
```

Стенды содержат проверки числа/положительности замеров, таймауты и проверку
целостности передачи. Оба выполнены успешно; Dart analyzer прошёл без замечаний.
Изменены только инструменты замеров, задача их сборки и этот отчёт; продуктовый код не менялся.
