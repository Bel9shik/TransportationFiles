# TransportationFiles

Передача одного файла между устройствами в локальной сети: JavaFX на Windows, Linux и macOS; отдельное Android-приложение с тем же сетевым ядром.

## Запуск на компьютере

Нужен JDK 17. Для сборки Android Lint используйте JDK 21 и установленный JDK 17 для Java toolchain.

```sh
./gradlew run
```

В PowerShell: `./gradlew.bat run`. На Linux для JavaFX нужна графическая сессия и GTK 3 (`libgtk-3-0`). JavaFX-библиотеки выбираются для ОС и архитектуры машины сборки. Целевые desktop-платформы: Windows x64, Linux x64, macOS Intel / Apple Silicon. Linux ARM и Windows ARM отдельно не проверены.

1. На получателе нажмите «Принять» / «Получить файл» и оставьте экран ожидания открытым.
2. На отправителе выберите файл и устройство. Если автопоиск не сработал, введите IP:порт с экрана получателя.
3. На компьютере кнопка «Принять» сохраняет файл в папку по умолчанию («Загрузки»). «Сохранить как…» позволяет выбрать папку и имя только для этого файла. При обычном приёме совпадающие имена получают номер: `photo (1).png`; существующие файлы не перезаписываются.
4. Во время передачи показываются GIF и прогресс. После сохранения и проверки файла на экране появляются слова «Файл отправлен» / «Файл получен» без всплывающего уведомления. До подтверждения получателя даже 100% означает ожидание проверки. Кнопка отмены прерывает незавершённую передачу.

В главном окне Windows/macOS/Linux есть настройка «Папка для полученных файлов»: «Выбрать папку…» сохраняет выбор между запусками, «Вернуть „Загрузки“» сбрасывает настройку. На Windows учитывается системный путь Downloads, на Linux — `xdg-user-dir DOWNLOAD`; если определить его не удалось, используется `Downloads` внутри домашней папки. Если выбранная вручную папка стала недоступна, приложение предлагает выбрать другую и не меняет место сохранения молча.

## Сборка desktop-приложения

```sh
./gradlew :app:packageApp
```

В `app/build/package/` появится приложение со встроенной Java: `.app` на macOS, папка с `.exe` на Windows, исполняемая папка на Linux. Собирайте на целевой ОС и архитектуре: один JAR с native JavaFX не является универсальным установщиком. `:app:distZip` отдельно создаёт архив запуска, требующий установленную Java 17.

CI в `.github/workflows/build.yml` выполняет тесты, сборку и запуск готового приложения отдельно на Windows, Linux и macOS. Проверка запуска: `python scripts/smoke_package.py` после `:app:packageApp`; она запускает приложение из временного каталога с пробелом в имени. Подпись, notarization и публикация установщиков не настроены; локально собранное macOS-приложение не подписано Developer ID.

Иконка приложения — вариант `design/app-icons/03-paired-files.png`. Из него подготовлены PNG для окна JavaFX и Linux, ICO для Windows, ICNS для macOS и Android mipmap-ресурсы. Готовые ресурсы хранятся в репозитории; для обычной сборки конвертер изображений не нужен.

## Android

Минимальная версия — Android 8.0 (API 26). Нужны Android SDK Platform 36, Build Tools 36.0.0, `ANDROID_HOME` или `sdk.dir` в локальном `local.properties`.

```sh
./gradlew -Pandroid=true :android:assembleDebug :android:lintDebug
```

APK: `android/build/outputs/apk/debug/android-debug.apk`. Android-модуль включается явно, поэтому desktop-сборка не требует Android SDK. Android Studio открывает корень проекта с Gradle property `android=true` (можно задать локально в пользовательском `~/.gradle/gradle.properties`).

- Выбор исходного документа и экспорт полученного файла используют системные диалоги Storage Access Framework, без доступа ко всему хранилищу.
- Исходный документ копируется в кэш перед отправкой, чтобы получить точный размер и стабильные данные. Нужно свободное место для копии.
- Полученные файлы хранятся в личном каталоге приложения. «Сохранить полученный файл…» экспортирует копию; отмена или ошибка экспорта сохраняет оригинал. Удаление приложения удалит неэкспортированные файлы.
- Принимайте и отправляйте с открытым приложением. Фоновая передача через Android foreground service не реализована; ОС может остановить процесс в фоне. Экран остаётся включённым, пока приложение открыто.

## Сеть и совместимость

`core` содержит gRPC/OkHttp, потоковую передачу блоками 64 KiB с регулированием скорости, SHA-256 и проверку размера. `proto` генерирует protobuf-lite для обеих платформ. Netty и обходы его внутренних полей на macOS больше не используются.

Каждая передача требует подтверждения и одноразового токена. Запрос ожидает 60 секунд; после согласия отправитель должен начать за 60 секунд; передача ограничена 10 минутами. Одновременно допускается один входящий файл. Незавершённый файл записывается во временный `.part` и удаляется при отмене/ошибке; после проверки он перемещается на выбранное место без перезаписи. После аварийного завершения процесса временный `.part` может остаться.

Автопоиск: UDP multicast `239.255.44.45:4445` и broadcast в каждой доступной IPv4-подсети, срок жизни записи 15 секунд. Point-to-point интерфейсы VPN пропускаются, broadcast отправляется с адреса LAN-интерфейса. На экране выбора получателя есть статус и кнопка «Повторить поиск». Источник адреса — сетевой пакет. Ручной адрес поддерживает `IP:порт` и `[IPv6]:порт`. Разрешите входящие соединения приложению в firewall. Гостевые сети, VPN, изоляция клиентов и блокировка multicast могут мешать обнаружению; в VPN включите разрешение доступа к локальной сети (Allow LAN). Ручной адрес помогает только при наличии прямой сетевой связности; приложение не обходит фильтрацию VPN или ОС. На macOS режим firewall «Блокировать все входящие подключения» блокирует и приём файла, и ответы автопоиска. В «Системные настройки → Сеть → Брандмауэр → Параметры» можно проверить этот режим и разрешение TransportationFiles; приложение само настройки не меняет. При запуске из Gradle разрешение требуется Java, а для готовой сборки — TransportationFiles.app.

**Передача не шифруется, имя устройства не удостоверяется. Используйте доверенную локальную сеть.** Токен связывает поток с согласием, но не защищает от перехвата трафика. Старая незавершённая версия приложения несовместима: обновите обе стороны. gRPC-методы сохранены, добавлены версия протокола, размер, токен и контрольная сумма; старые небезопасные запросы отклоняются.

## Проверки

```sh
./gradlew :core:test :app:test
# На Linux без дисплея:
xvfb-run -a ./gradlew :core:test :app:test
# При подключённом Android-устройстве / эмуляторе:
./gradlew -Pandroid=true :android:connectedDebugAndroidTest
```

Тесты ядра используют реальные loopback-соединения: пустой и многоблочный файл, Unicode, отказ, отмена ожидающего запроса, повреждение/обрезание/превышение размера, неверный токен, небезопасные имена, запрет перезаписи. JavaFX smoke-test загружает экраны, отправляет и принимает файл, проверяет GIF, итоговый текст без всплывающих окон и отсутствие преждевременного успеха до подтверждения получателя. Снимки экранов сохраняются в `app/build/reports/screenshots/`. Android instrumented test выполняет передачу внутри Android runtime.

Для проверки обнаружения двух участников на одном компьютере без ручного адреса: `TRANSPORT_DISCOVERY_TEST=true ./gradlew :core:test --tests '*DiscoveryNetworkTest' --rerun-tasks` (PowerShell: сначала `$env:TRANSPORT_DISCOVERY_TEST="true"`). Для проверки передачи через собственный LAN-адрес используйте `--tests '*TransferLanTest'` с той же переменной окружения. Обе проверки включены в desktop CI; локально он требует доступной LAN и разрешённого UDP. Он не заменяет проверку между двумя физическими устройствами. Отдельный обычный тест проверяет отправку broadcast при отказе или молчаливой потере multicast.

Для отдельной проверки Android → desktop → Android запустите стандартный Android-эмулятор, выполните `adb forward tcp:50072 tcp:50072`, затем в одном терминале `./gradlew :core:interopDesktop`, а в другом:

```sh
./gradlew -Pandroid=true -Pandroid.testInstrumentationRunnerArguments.desktopInterop=true :android:connectedDebugAndroidTest
```

Тест использует `10.0.2.2:50071`, отправляет 1 048 577 байт, получает их обратно и сравнивает данные. Завершив проверку, удалите перенаправление: `adb forward --remove tcp:50072`.

## Что проверено локально (25 октября 2026)

На macOS Apple Silicon прошли 28 тестов ядра и JavaFX smoke-test; собранное `.app` запущено со встроенной Java. APK собран, Android Lint завершился без ошибок (есть предупреждения о версиях инструментов, локализации и оформлении). На Android 17 в эмуляторе прошли пустая/многоблочная передача и отдельный двусторонний тест с desktop JVM. Android 8–16 и физические Android-устройства не проверены. В [GitHub Actions](https://github.com/Bel9shik/TransportationFiles/actions/runs/40187006202) прошли desktop-задачи Windows, macOS и Linux: 28 тестов ядра, JavaFX-тест с показом окна, сборка и запуск готового приложения со встроенной Java. Для Java-компиляции явно задан UTF-8; тесты также прошли локально при системной кодировке Windows-1252. Передача между физическими Windows/macOS-устройствами через Wi-Fi пока не проверена.
