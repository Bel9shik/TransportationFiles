# TransportationFiles

Передача файлов в локальной сети для Android, Windows, Linux и macOS. Новое приложение находится в `flutter_app/`: общий интерфейс и сетевое ядро на Flutter/Dart, release-сборки с AOT-компиляцией без JVM на компьютере. Небольшой Android-адаптер отвечает за системные папки, буфер обмена и multicast lock.

## Использование

1. Подключите устройства к одной локальной сети. На получателе откройте «Принять файлы».
2. На отправителе выберите до 200 файлов и устройство из списка. Можно указать IP:порт с экрана получателя вручную.
3. Подтвердите приём. По умолчанию используются «Загрузки»; папку можно изменить в главном окне или для конкретной передачи. На Android копия сохраняется в `Загрузки/TransportationFiles`, а полученные файлы также остаются внутри приложения для повторного экспорта.
4. Дождитесь текста «Отправка завершена» / «Приём завершён». 100% отправленных байтов ещё означает ожидание проверки и сохранения получателем. Отдельных уведомлений об успехе нет.

Пакет подтверждается один раз. На компьютере он сохраняется в новую папку `Файлы-…`. Одинаковые имена получают номера. Размер и SHA-256 проверяются для каждого файла; при отмене или ошибке временные файлы удаляются. Существующие файлы не перезаписываются, в том числе если они появились после подтверждения приёма.

После приёма можно выбрать один, несколько или все файлы для буфера обмена. Одно изображение PNG/JPEG/GIF/BMP/WebP до 40 Мп копируется на компьютере как изображение (GIF — первый кадр), несколько файлов — как список файлов. На Android используются content URI с MIME-типами и временным доступом для чтения; для нескольких фотографий есть системное меню «Поделиться». Поддержка вставки зависит от целевого приложения. «Сохранить как» позволяет экспортировать полученное повторно.

Автопоиск использует UDP `239.255.44.45:4445` и directed broadcast через локальные IPv4-интерфейсы. gRPC-сервер запускается автоматически на свободном TCP-порту после появления окна. VPN может блокировать локальный трафик; приложение не меняет настройки Tunnelblick, firewall или маршрутизации. Передача не шифруется, имя отправителя не удостоверяется: используйте доверенную сеть.

## Разработка и сборка

Нужен **Flutter 3.47.9 / Dart 3.13.7**, для Android — Android SDK и JDK 21. Для desktop-сборки нужны инструменты целевой ОС: Xcode на macOS, Visual Studio с Desktop development with C++ на Windows, clang/CMake/Ninja/GTK 3 на Linux.

```sh
cd flutter_app
flutter pub get --enforce-lockfile
flutter run
flutter analyze
flutter test

# Выполнять на соответствующей ОС:
flutter build windows --release
flutter build macos --release
flutter build linux --release
flutter build apk --release
```

На Windows `ISCC.exe packaging/windows.iss` создаёт один EXE-установщик из release-сборки. Установщик не подписан. На macOS Developer ID и notarization не настроены. Android собирается в **release/AOT**, но пока подписывается локальным тестовым ключом: это не production-подпись и не гарантия обновления поверх APK из другого CI-запуска.

GitHub Actions собирает Windows x64, Linux x64, macOS ARM64/Intel и Android. В артефактах запуска workflow доступны архивы приложений, Windows EXE и APK. Публикация в Releases выполняется отдельно после проверки. Linux/Windows ARM и физические устройства не охвачены этой матрицей.

## Проверки и время запуска

Тесты используют реальные gRPC-соединения: пустые и многоблочные файлы, подборки, Unicode, отказ, неверный токен, испорченный поток, отмена и защита существующего файла. Проверяются выбор файлов и закрытие диалога при отмене отправителем.

Совместимость с текущей Java-версией проверяется в обе стороны (нужны JDK 17 и Dart в PATH):

```sh
python3 scripts/test_flutter_interop.py
```

В CI после сборки запускается `python scripts/compare_startup.py`: по пять отдельных процессов Java и Flutter на одном runner, вне каталога проекта. Измеряется время до первого нарисованного кадра; дополнительно проверяется запуск gRPC у Flutter. Результаты — в `startup-results.json` и сводке Actions. Кэши ОС не очищаются; это не замер установки, SmartScreen/Gatekeeper или скорости передачи. Debug-запуск через IDE не сравнивается с release.

Локальная исходная Java-сборка на macOS ARM64: 1,724 / 0,553 / 0,526 с до первого кадра. Это исходная точка сравнения, а не доказательство причины задержки на другом компьютере.

## Совместимость и переход

Протокол и объявления устройств сохранены: одиночные файлы и пакеты совместимы с Java `v1.1.0-preview.1`. Старые Java-модули оставлены для межъязыковых тестов и сравнения запуска; они не входят в новую desktop-сборку. Их инструкции — в [docs/legacy-java.md](docs/legacy-java.md), отдельный ручной workflow — `Legacy Java packages`.

Новая desktop-версия хранит настройки отдельно: пользовательскую папку приёма нужно выбрать заново. Windows устанавливается отдельно от Java-версии в `TransportationFiles-Native`; после проверки старую версию можно удалить обычным деинсталлятором. Android application ID сохранён. Если ключ подписи отличается, не удаляйте старое приложение до экспорта нужных внутренних файлов. Новая версия видит прежний Android-каталог полученных файлов.

Dart-файлы gRPC сгенерированы из `proto/src/main/proto/transport_files.proto`. Для обновления из каталога `flutter_app`:

```sh
protoc --plugin=protoc-gen-dart=tool/protoc-gen-dart --dart_out=grpc:lib/generated -I../proto/src/main/proto ../proto/src/main/proto/transport_files.proto
```
